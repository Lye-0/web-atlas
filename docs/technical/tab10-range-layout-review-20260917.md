## F1 集合の範囲判定

vehicle-definition固定入力の「対象環境未特定」でwebを選び、図の認証3/HTTP54/HTTP28の集合と強調関係があるのに、詳細の全3集合が範囲外になる症状を実ブラウザで再現。

原因はcontentAllowedIdsが正規対象のID集合なのに、詳細欄がarchitecture-displayの表示IDを直接hasで調べていたこと。表示名・件数の一致ではなく、投影のrequestIdsとrequestGroupsのメンバー対応を使うcoverageへ変更。現在の残集合のrequestIdsを優先し、取り出した要求を二重に加算しない。未描画/画面外の正規対象も包含を保持する。

全件内は範囲外にしない。一部だけなら「一部を表示（この内容：N/M対象）」、全件外は従来の範囲外と明示移動を維持。全体へ移る集合は元メンバーへ移動し、集合IDを実階層として扱わない。coverageは範囲と投影に応じて再利用し、カメラで全件展開しない。

相手の包含と個別の関係の包含も分離。両端が範囲内でも、プリセットに入っていない正規関係は「この関係は表示内容の範囲外」と説明し、図で選択するボタンを出さない。対象や線は追加しない。

修正後、webの上記3集合から誤った範囲外表示が消えた。28要求の1件を取り出した後、別プリセットを往復しても27+1と元選択/カメラが一致。DB変更側のlocal DB詳細では、範囲に含めないAPIのdevelopment実行構成に正当な範囲外表示が残る。HTTP解析は変更していない。
