## 原因と修正

以前は同じアプリ向けの開発・ビルド・起動・公開をまとめ、起動先を論理アプリへ吸収していた。元関係を保存しても、原本→操作→同じ原本の往復になり、近接配置では分岐が読めなかった。

- F1 原本・定義を左列に揃える。論理アプリ、共有コード、定義と、既存の実行構成を分離する。新しい実体は作らない。
- F2 操作用途を分ける。道具・用途・設定・作業場所・入力・出力・環境・条件・引数が対応する使用だけ同じ説明単位へまとめる。script名の違いだけなら内訳にする。
- F3 入力・生成・起動・公開・適用の元関係で枝を作る。二つ以上の操作へ渡る成果物は図に残す。複数原本からの合流点を複製しない。
- F4 記録された処理関係の深さを列、用途別の枝を行にする。到着先は右列。コード参照・通常通信は残すが順序の制約にはしない。循環はSCCと訪問済み集合で有限に扱う。
- F5 同じ要約で2D/3Dを描画する。3Dには枝ごとの奥行きを加える。囲いは単一原本に由来する経路の補助表示とし、別対象を巻き込むものを省く。
- F6 名前変更fixture、実入力スナップショット、既存回帰テストで確認する。配置にプロジェクト名・技術名・特定環境名の分岐はない。

変更中心は `architectureSimple.ts`、`architectureSimpleGroups.ts`、`architectureSimpleUsage.ts`、`architectureSimpleLayout.ts`。ページ/詳細欄は役割説明を更新。解析器・共通グラフレンダラー・既存プリセットの処理は変更していない。
