## 実操作で確認した契約

**検索と選択。** Aの8件打ち切り・1件一致の自動選択を除去し、全論理候補を共通の固定1行Stripへ渡す。0件・1件・多数一致、Endでの末尾選択、同名packageの別パス、長いコマンドを確認した。入力前後のNode styleとEdge `d`は一致し、検索消去と検索欄のEscapeは選択とカメラを保持した。明示フィルターから外れた選択は消え、開始コマンドは検索と独立する。

Workspaceの共通Stripは390×844のタッチエミュレーションでも確認した。24候補を23回のスクロール操作で末尾まで送り、最後の候補をタップして選択できた。

**カメラとパネル。** A/BのResetはカメラだけを変更する。Aは既存の初期transform、Bは表示範囲の初期Fitを用い、検索・選択・展開を消去しない。選択へ移動はNode/Regionを表示し、Edgeなら両端と現在の経路を収める。空白解除とドラッグを区別し、詳細閉鎖は選択を保つ。全画面中のメニューEscape、終了Escape、Tabの範囲を確認した。Dictionaryリンクから戻ってもscanVersionと選択は保持された。

**ブロックと根拠。** 既存のSummary展開と選択ブロック内Evidenceを維持。サイズが変わっても矢印・粒子は現在のrouting結果を使う。コード欄のクリック・ArrowDown・ホイールが選択／ズームへ伝播しない。詳細はファイル名・行番号・完全パスとコード、補助情報の開閉を揃えた。Moduleのimport先／元では対象数と関係数を併記し、未解決は「宣言は確認でき、範囲内の参照先は特定できない」と説明する。

**粒子。** 共通の通常／控えめ／オフ設定は全10タブの往復・project replacementで保持された。Aは選択関係だけに粒子を表示し、source→targetと同じSVG経路で負のdash offsetが進むことを実測した。通常は2つ、控えめは1つの小さいdashで遅くし、動き軽減では静止。OFFや画面外では粒子要素を除去する。Bの双方向importは入る橙／出る青を保ち、通常・控えめで2本を動かし、OFFで2本の静止線を残してループを停止した。

**タブ6〜10。** 各タブをgit-linesとvehicle-managementで個別に開き、通常／控えめ／オフの描画状態、選択付き2D/3D往復、4画面幅を確認した。6〜9は追加でgit-linesの自動省略ON/OFFそれぞれにおいて、選択→詳細閉鎖→回転／ズーム→空白解除→再選択を確認し、解除後の選択由来pathは全ケース0件。タブ10は両実プロジェクトで各39項目の階層・現在地・外側選択・内部への移動・戻る操作が通った。

同じ固定入力、1440×1000、計測関数を付けたproductionビルドで静止・選択・実際のパン・展開を比較した。静止／パンでは修正前後ともlayoutとroutingの呼び出しが0回。選択／展開では両方ともlayout 2回、routing 1回で、必要なサイズ変更だけを反映した。

通常／控えめの静止計測でも連続layout／routingは0回。別途、選択Edgeが画面内で実際に動いていることを確認してA2〜4のパンを両プロジェクトで計測した。動く線は各1本で、通常2粒・控えめ1粒。対象数・表示線数と各モードの数値はmetricsに記録している。

初回のgit-lines / Workspace通常は計測末尾の粒子が0本だったため、粒子ONの評価には用いず、1本の可視・有効状態を確認した補足計測を採用した。

フレーム応答に大きな差は観測されなかったが、単一の対応測定には時間のばらつきがあり、CPU時間の一律改善は主張しない。特にPackage Dependencyの選択やCommandの大きな展開には既存の50ms超タスクが前後とも残る。RAF間隔はGPU描画時間や全環境の応答保証ではない。今回の共通化による継続的な高コスト処理の追加がないことを確認し、routingの再設計は対象外とした。
